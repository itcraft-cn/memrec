## 三、明确不做（已否决，避免反复讨论）

| 项 | 理由 |
|---|---|
| 实体维度（Entity） | 开放世界维度，`type_n × tag_m × entity_l` 组合面与跨记忆链接无界膨胀，抽取不稳定 |
| Web 记忆查看器 | 记忆的消费者是 LLM，人看收益有限；仅保留机器可读 `DreamReport` |
| 多模态记忆 | 文本单客户端模型 + 需轨迹级写入契约（前序已否决） |
| 多 Cube 多租户 | 架构级多租户，与前序否决一致；保持项目+全局两态 |
| Host Bridge / 插件生态 | 前序已否决 |
| L1/L2/L3 独立分层子系统 | 与"记忆融合不按用途切分"冲突；抽象阶梯应是 dream 产出 |
| "永不压缩"（Mem0 的 ADD-only 全盘照搬） | 保留 dream 压缩；只吸收"不覆盖"，不吸收"不整合" |

## 四、需先敲定的两个口径

### 4.1 "人工显式意图放行"如何落地——以**操作语义**替代**调用者身份**

问题：memrec 无第二个客户端、无可信调用者标识，且 LLM 与"人"走**同一个入口**。
若把"是否允许修正历史"做成一个参数（如 `human=true`），**LLM 会照样传入**，约束形同虚设。

结论：**放弃调用者身份维度**，改为按**操作语义 + 可逆性 + 审计**约束，全部由服务端依据记忆属性（`created_at`）判定，无法被调用方绕过。

| 操作类 | 触发 | 约束 | 是否可被调用方绕过 |
|---|---|---|---|
| **自动整合类** | `Add` 内置去重；dream 合并/软删 | 按记忆**年龄窗口**：窗口内可原地更新；窗口外不原地覆盖 | 否（服务端内部逻辑，非参数） |
| **显式操作类** | Add 新记录 / Update / Delete / Restore | **不再原地覆盖**：显式"修正"= 新增 + 旧记录标 `superseded`（软）；**删除一律软删可恢复** | 安全（可逆、可审计），故统一放行 |
| **不可逆类** | 硬删 `force=true` | **唯一不可逆操作**，单独收紧：默认关、显式确认路径、全程审计 | 收紧处理 |

即：**对所有人（含 LLM）统一放行显式操作**，因为显式修正已被版本化、显式删除已被软化；
"放行"不再依赖"是不是人"，而依赖"操作是否可逆"。这样即使 LLM 偷调，最多产生一个可恢复、可审计的版本，不会毁掉历史。

> 附带收益：`Update` 语义统一为"窗口内原地更新 / 窗口外版本化新增"，行为可预测、可测试。

### 4.2 评级作用域

- 每记忆 `importance` 仅作**全局先验**；
- dream 评级为**簇域**（附着于该簇的摘要/事实条）；
- 检索分 = 全局先验 × 查询期相关度。

## 五、与"真正要做的"对应的底线（不变量）

1. 记录路径零 LLM（不变）。
2. 整合幂等（`source_ids` 机制保留）。
3. 源可恢复（软删 + RocksDB 留存 + archive）。
4. 失败不刷新 `last_run_at`。
5. 命名正交（不复用 `Scene`；用 `DreamRun` / `LlmEdgeGenerator` / `EdgeBuilder` / `DreamReport`）。
6. **内容不因"谁调用"而被区别对待**；安全来自可逆与审计，而非调用者身份。

---

## 六、一句话总括

**要做的**：先立标尺（评测），再建底座（DreamRun + 更新窗口），然后上主体（Stage F 融合、Stage N 成网、检索走图），最后按需开语义边与中价值项。
**不做的**：一切把记忆切碎、把维度开放、把控制权外移的架构级主张。
